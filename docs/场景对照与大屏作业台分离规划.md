# 场景对照评估 + 大屏/作业工作台分离规划

> 版本 v1.0 · 2026-08-13
> 依据：`files/学员材料-Echo阶段输出材料包/`（ECHO-01~05）+ `docs/场景模块补全实施计划.md` + 当前代码
> 结论先行：**10 场景中 8 个已实现且"规则可解释"的处理是合理的**；**当前最大的结构问题是大屏(S1)与作业功能(S2/S7/S8/S10)耦合在同一个页面**，应分离。

## 一、10 场景完成度对照（材料需求 vs 当前实现 vs 合理性）

| 场景 | 材料需求 | 当前实现 | 合理性评价 |
|---|---|---|---|

**总体判断**：现有实现"规则可解释、不承诺伪 AI、S6/S9 按材料教训暂缓"的取舍是**正确的**，符合 Echo 材料审查结论。**唯一需整改的是架构层面的耦合**（见下）。

## 二、核心问题诊断：大屏与作业功能耦合

当前 `DashboardView.vue`（400+ 行）把**两类性质完全不同的功能**塞进同一个页面：

| | 指挥大屏（S1 本质） | 作业功能（S2/S7/S8/S10/S6 本质） |
|---|---|---|
| 使用者 | 领导/指挥中心 **看** | 调度员/飞手/委办局 **操作** |
| 形态 | 16:9~48:9 大屏、全屏、只读展示 | 桌面工作站、表单交互、状态流转 |
| 权限 | 只读 viewer | 需要 operator/admin 写权限 |

**具体后果**：
1. 大屏右列被 5 个页签（排行榜/智能调度/工单/健康/分析）挤占，管理表单污染了"一张图"的汇报界面；
2. 作业人员没有独立工作台，操作入口深埋在大屏的窄栏里；
3. 路由只有 `/`，单一角色 `dashboard.viewer`，**无权限边界**——大屏只读与作业写入用同一凭证；
4. 单文件 400+ 行难维护，SSE/轮询/抽屉/回放/告警逻辑全部混在一起。

**结论：大屏与作业功能应当分离。** 这与材料痛点 P4（"大屏是展示需求"）与 S1（唯一高颗粒度展示场景）的判断一致。

## 三、目标架构

```
/login               登录（不变）
/                    指挥大屏 BigScreen —— 纯 S1 态势总览（只读，48:9 自适应）
                     ├ 三栏：飞行总览/案例TOP10 | 地图+实时告警 | 任务排行榜
                     ├ 实时告警呈现（S3 冲突/S4 低电量/S5 禁飞区，只读）
                     └ 角色：dashboard.viewer

/workspace           作业工作台 OpsWorkbench —— 操作型场景（桌面布局，非 48:9）
                     ├ S2/S8 智能调度推荐（派发、应急优先）
                     ├ S7 巡检工单闭环（状态流转、自动生成）
                     ├ S10 设备健康维护
                     ├ S6 AI 事件处置（演示事件流 + 确认/转派/归档）
                     ├ S9 数据问答（预留入口，需先做指标字典+权限+SQL沙箱）
                     └ 角色：operator / admin
```

**共享能力**（抽离为 composable，两页复用）：
- `useAircraftStream`（SSE 重连/退避/401）
- `usePolledResource`（30s 轮询 + last-good + stale 徽标）
- `OperationsMap`（地图组件，大屏全幅 / 工作台缩小嵌入）
- `ReplayDialog`（回放小窗，两页共用）
- API 层（不变）

## 四、分阶段实施计划

### Phase 0 · 能力抽离（0.5 天）
- 从 `DashboardView` 抽 `useRealtimeAlerts` / `useAircraftStream` / `usePolledResource` 到 `src/composables/`
- 后端 `auth.ts` 增加角色：`operator`（作业）、`admin`（管理），登录时按用户下发（默认 admin 持全角色）
- 路由守卫支持 `meta.roles` 校验

### Phase 1 · 作业工作台骨架 + 面板迁移（1 天）
- 新建 `views/OpsWorkbench.vue` + 路由 `/workspace`（`meta: { requiresAuth, roles: ['operator','admin'] }`）
- 布局：顶栏（复用 command-header 精简版）+ 左侧功能导航（智能调度/工单闭环/设备健康/AI 事件/数据问答）+ 内容区
- 迁移：`DispatchPanel`、`WorkOrderPanel`、`HealthPanel` + 新增 AI 事件处置面板；`OperationsMap` 缩小嵌入（可折叠）
- 大屏右列**移除** 智能调度/工单/健康 三个页签，只保留「排行榜」与「飞行统计分析」（二者是展示指标，属 S1 范畴）

### Phase 2 · 大屏瘦身 + 告警闭环（0.5 天）
- `DashboardView` 精简为纯展示：三栏 + 告警抽屉（只读查看，去掉作业类按钮）
- 大屏告警抽屉增加「转工单」入口 → 跳转 `/workspace` 并预填（打通 S3/S4/S5 告警 → S7 工单的处置闭环）
- 验证 48:9（5120×1440/7680×1440）与 16:9 适配、E2E 矩阵全绿

### Phase 3 · 权限与安全（0.5 天）
- 大屏路由仅 `dashboard.viewer`；工作台路由 `operator/admin`；导航按角色隐藏入口
- 无权限访问重定向 + toast；后端对写接口（派发/工单流转/生成）增加角色校验
- 审计：作业类写操作记录操作人/时间（满足材料"登录行为全程审计"）

### Phase 4 · 暂缓项独立立项（待数据条件成熟）
- **S9 数据问答**：前置依赖——业务指标字典、跨部门权限模型、SQL 沙箱、幻觉兜底（材料 4 项风险逐一有方案后才启动）
- **S6 真实图像识别**：前置依赖——历史样本/标注集、类别边界定义、光照/天气条件下的基线测试、误报漏报责任流程；当前保留演示事件流

## 五、验收标准（分离完成后）

- [ ] `/`（大屏）与 `/workspace`（作业台）路由隔离，互不依赖对方组件
- [ ] 大屏右列不再出现管理表单页签，48:9/16:9 无溢出
- [ ] 作业台 4+1 个功能可用（调度/工单/健康/AI事件/问答入口），桌面布局无横向滚动
- [ ] 角色隔离：viewer 只读大屏、operator 可作业、admin 全量；越权访问被拦
- [ ] 告警→工单闭环链路打通
- [ ] `npm run typecheck` / `npm test` / `npm run build` / `npm run e2e` 全绿，E2E 新增工作台规格
