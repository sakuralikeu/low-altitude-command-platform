## 1. 项目一句话介绍

> **面向市级指挥中心的无人机低空指挥调度平台**：一张大屏看全域态势（飞机实时位置、禁飞区、冲突、告警），一个工作台做智能调度（推荐派机、航线规划、工单闭环、设备管理），所有规则可解释、可演示、可审计，不装没有数据支撑的假 AI。

某城市低空经济试点区拟建设低空无人机常态化管控能力：公安、交管、水务、消防、城管等 10 余家委办局联合，通过**统一调度一架或多架无人机**，实现"态势一张图"的可视化与巡检决策支撑。客户现状痛点（Echo 材料 ECHO-02）：

## 5. 核心功能模块

### 5.1 指挥大屏（S1）
- 顶栏：品牌、LIVE 呼吸灯、时钟（每秒隔离渲染）、日期天气、同步状态、刷新、全屏、用户
- 左栏：飞行总览（9 个接口字段全上屏，count-up 动画）+ 飞行案例 TOP10（点击轨迹回放）
- 中栏：地图（高德三底图/演示底图）+ 三个 KPI（执行中/告警/任务，可点击抽屉）
- 右栏：任务排行（5 档周期 × 4 种状态 × 组织占比）+ 飞行分析（3 指标切换）
- 告警抽屉：执行中飞机 / 运行告警（飞机告警 + 空域合规事件）/ 今日任务 / 航线目录（可搜索）
- 快捷键：`F` 全屏、`R` 刷新（输入态不拦截）

### 5.1.1 业务流程详解（答辩必背）

#### 流程一：工单闭环（S7）——"任务的提出 → 承接 → 执行 → 结案 → 资源释放"

**四类来源**（`source` 字段）：`plan`（按航线周期自动生成）/ `dispatch`（派发成功自动建单）/ `alert`（告警转工单）/ `maintenance`（保养工单）

**状态机**（合法流转表驱动，非法 409）：
```
pending 待接收 ──接收──▶ received 已接收 ──开始执行──▶ executing 执行中 ──结案──▶ completed 已完结
```

**完整故事（告警驱动）**：SSE 推低电量告警 → 大屏 toast → 抽屉"转工单" → 生成 pending（source=alert + sourceAlertId 溯源）→ 接收（received）→ 开始执行（executing，**联动飞机起飞**：flying + 任务=工单标题）→ 结案（completed，**联动飞机释放**：回待命、清目标；若占用规划航线则释放回 planned 并落盘）

**闭环的本质**：工单不是孤立表单——它是状态中枢，每走一步同时收敛"飞机状态 + 航线状态"，全链路可溯源。

#### 流程二：智能调度（S2/S8）——"派哪架、去哪个点、干什么"

**调度目标（任务点 lng/lat）5 个入口**：① 面板 4 个预设位置 ② 地图空白点选 ③ 点地图飞机带入当前位置 ④ URL 参数（方舱"去调度"跳转带坐标）⑤ AI 事件转派（事件发生地坐标）

**决策四步**（`recommendDispatch`）：
```
① 候选过滤：机型能力匹配（M350 RTK 全能 / M30T 巡逻+巡检 / M3E 巡检+应急）
           + 非下线 + 无未完结工单（防重复派发）+ 电量 ≥25%
② 加权评分：距离分（Haversine，1-d/12km 归一）× 权重
           + 电量分 × 权重 + 空闲分（待命1/执行0.35/告警0.5）× 权重 + 机型能力分 × 权重
   权重按任务类型：巡逻 40/30/20/10 · 巡检 45/30/15/10 · 应急 60/25/10/5
③ 排序取前 N（应急 3 / 其他 5），每条附可解释理由
④ 派发落地：二次确认 → applyDispatch（飞机起飞+写入目标）→ 自动生成工单
   → SSE 驱动飞机飞向目标（可选沿航线依次过航点）
```

#### 流程三：巡检计划生成（S7 的 plan 来源）——"航线 × 周期频率 × 同日去重"

| 周期 | 航线（关联单位） |
|---|---|
| 每日 daily | 中心城区航线（公安局）、河道巡检航线（水务局）、重点道路巡检（交通局） |
| 每周 weekly | 市容巡查航线（城管局）、重点区域瞭望（消防支队） |

生成逻辑（`generateWorkOrders`）：遍历 LINE_PLAN 匹配周期的航线 → 若该航线**当天未生成过**（lineName + 日期去重）→ 创建 pending 工单"XX单位日常/周期巡检计划"；已存在则跳过。

**与客户设想的差异（答辩要点）**：客户设想"AI 根据历史规律自动生成"，但无历史数据支撑 → 本项目做**规则版频率计划**（周期明确、去重明确、可解释）。接真实系统后，LINE_PLAN 可替换为"按历史任务频次统计学习出的推荐周期"，接口不变。

### 5.2 智能调度（S2/S8）
- 输入：任务类型（巡逻/巡检/应急）、位置（预设/地图点选/飞机带入/URL 参数）、优先级
- 推荐：候选过滤 → 加权评分 → 排序 + 可解释理由（"距目标 2.1km，电量 82%，预计续航 41min"）
- 派发：二次确认 → 飞机起飞（standby→flying）→ 生成工单 → SSE 驱动飞向目标
- 沿航线执行：可选用地图规划航线，飞机依次飞经航点

### 5.3 空域安全（S3/S4/S5）
- 冲突：任意两架飞行中飞机 Haversine 水平距离 + 高度差，双阈值分级，SSE 推送 + 地图连线
- 续航：机型额定续航 × 电量百分比，返航阈值 = 去程所需电量 × 1.25 安全系数
- 禁飞区：多边形射线法判定，违规即告警（同机同区只报一次，离开后复位）

### 5.4 工单闭环（S7）
- 状态机：待接收 → 已接收 → 执行中 → 已完结（非法流转 409）
- 来源：计划生成（日/周）/ 调度派发 / 告警转单 / 保养工单
- 与飞机联动：执行中=飞机起飞，结案=飞机释放回待命、航线释放回计划

### 5.5 设备管理（S10）
- 健康分（飞行时长/电池循环加权）+ 部件寿命阈值（电池 300 循环/电机 800h/桨叶 400h）
- 低分一键生成保养工单；下线/恢复（下线后不参与调度、遥测悬停、不告警、地图置灰）

### 5.6 方舱下钻
- 6 个启用方舱（地图 Warehouse 标记）+ 5 个规划中
- 点击弹窗显示驻泊无人机（机型/状态/电量）→ 一键"去调度"预选该机

### 5.7 航线规划
- 地图连续点击画线（双底图）→ 命名保存 → 进首页航线目录（可搜索）
- **JSON 文件持久化**（Docker volume），重启不丢；创建/派发/结案状态均实时落盘

### 6.1 调度推荐引擎（S2 核心，`scenarios.ts`）

```ts
const WEIGHTS = {
  patrol:    { distance: 0.4, battery: 0.3, idle: 0.2, capability: 0.1 },
  inspect:   { distance: 0.45, battery: 0.3, idle: 0.15, capability: 0.1 },
  emergency: { distance: 0.6, battery: 0.25, idle: 0.1, capability: 0.05 },
}

export function recommendDispatch(taskType, lng, lat, priority) {
  const weight = WEIGHTS[taskType]
  const scored = aircraft
    .filter((item) => {
      const model = aircraftModels[item.model]
      if (!model || !model.capability.includes(taskType)) return false  // 机型能力匹配
      if (item.offline) return false                                    // 下线不参与
      if (hasActiveWorkOrder(item.name)) return false                   // 防重复派发
      if (item.batteryPercent < 25) return false                        // 低电量剔除
      ...
    })
    .map((item) => {
      const distanceScore = Math.max(0, 1 - distanceM / 12000)
      const score = distanceScore * weight.distance + batteryScore * weight.battery
                    + idleScore * weight.idle + capabilityScore * weight.capability
      return { ..., score, reasons: ['距目标 2.1km', '电量 82% · 预计可飞 41min', ...] }
    })
    .sort((a, b) => b.score - a.score)
}
```

**讲解口径**：① 为什么加权评分？规则可解释、无黑盒，评委能看懂每一分怎么来；② 权重为什么应急时距离调高到 0.6？应急场景"到场速度"优先于"空闲度"；③ reasons 数组让 UI 直接展示推荐依据，实现"可审计"；④ 三个过滤条件分别回答：机型能不能干、飞机在不在、有没有重复任务。

### 6.2 SSE 实时链路 + 沿航线飞行（`data.ts` / `app.ts`）

```ts
// app.ts —— SSE 端点：2s 一帧 + 15s 心跳
app.get('/api/v1/realtime/aircraft', authenticate, (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream')
  ...
  const send = () => {
    const snapshot = nextAircraftSnapshot(sequence)
    res.write(`event: aircraft\ndata: ${JSON.stringify({ sequence, rows: snapshot })}\n\n`)
    for (const event of detectRealtimeAlerts(snapshot, zoneState)) {
      res.write(`event: ${event.type}\ndata: ${JSON.stringify({ sequence, ...event })}\n\n`)
    }
  }
  send()
  const interval = setInterval(send, 2000)
  req.on('close', () => clearInterval(interval))
})
```

```ts
  executing: ['completed'], completed: [],
}

export function transitionWorkOrder(id, to) {

    throw new Error(`不允许从 ${order.status} 流转到 ${to}`)   // 非法流转 409
  order.status = to

  }

}
```

## 9. 部署架构与运维

### 9.1 部署链路
本地（Apple Silicon）→ `buildx --platform linux/amd64` 交叉构建 → `docker save` 压缩 → scp 到服务器 → `docker load` → `docker compose up -d --no-build`

> 关键坑位（答辩可提）：本机 arm64 与服务器 amd64 架构不匹配，必须交叉构建；`docker save/load` 离线传输使远端不依赖 npm/外网。

### 9.2 容器加固
- `read_only: true` + `tmpfs`（/tmp、nginx 缓存）+ `cap_drop: [ALL]` + `no-new-privileges`
- 资源限额（api 256m/1cpu，web 128m/0.5cpu）+ `pids_limit` + healthcheck
- api 只进 internal backend 网络；仅 web 暴露 80/443 端口
- api 非 root 用户（uid 10001），数据 volume 权限在镜像内预置

### 9.3 HTTPS
- 自签名证书（局域网演示用），HTTP 18080 + HTTPS 18443 双入口
- 白屏事故复盘：CSP `upgrade-insecure-requests` 会把资源强制升级 HTTPS → 无 SSL 服务 → 全挂；移除后恢复正常

## 11. 答辩 Q&A 速查（30 题）

### 架构与选型

**Q1：为什么用 SSE 而不是 WebSocket？**
A：需求是单向的（服务器推飞机位置/告警给大屏），SSE 语义完全匹配：基于 HTTP、自动重连、断线续传（Last-Event-ID 可扩展）、无需升级协议；WebSocket 适合双向交互（如遥测下行指令），本项目指令走 REST，不需要。SSE 成本更低、中间设备兼容性更好。

**Q2：数据为什么是内存态？不落数据库？**
A：演示系统三原则：① 确定性——重启复位保证演示可复现；② 零依赖——不需要评委现场配数据库；③ 分层——演示基线内存、**用户业务数据（规划航线）已 JSON + volume 持久化**。接真实系统时，数据访问层（data.ts）替换为仓储实现即可，接口契约不变。

**Q3：前端为什么不直接连数据库？**
A：BFF 模式。统一做鉴权、入参校验（zod）、错误格式（error+traceId）、角色守卫；前端不暴露内部结构；也符合材料"各部门共享能力"的诉求——所有接入方走同一 API。

**Q4：高德地图没 Key 会怎样？**
A：自动降级为本地演示底图（CSS 网格 + SVG 禁飞区），飞机标记、筛选、告警全部不受影响；CDN 加载失败有"重试"按钮；UI 明确标注"演示底图 · 待配置高德 Key"，不冒充真实地图。

**Q5：monorepo 有什么好处？**
A：npm workspaces 单仓库管理 web+api 两个包：统一依赖版本、一次 `npm ci`、一条 `typecheck/test/build` 命令链、CI 一次构建；边界靠 workspace 隔离。

**Q6：为什么用 zod？**
A：TypeScript 类型是编译期契约，zod 是运行期校验——API 边界必须运行期校验（外部输入不可信），zod 从 schema 推导类型，一处定义两端生效。

### 调度与闭环

**Q7：派发后飞机真的会动吗？**
A：会。派发调用 `applyDispatch`：standby→flying、任务文本更新、写入 `dispatchTargets`；SSE 快照每 2s 按目标直线插值，航向跟随、到达悬停；地图实时可见。演示时可现场验证：派发后回大屏看飞机飞向任务点。

**Q8：怎么防止同一架飞机被重复派发？**
A：三重过滤：① 已有未完结工单（pending/received/executing）的飞机从候选剔除；② 电量 <25% 剔除；③ 已下线剔除。候选列表本身就不出现"忙机"。

**Q9：工单流转和飞机状态怎么联动？**
A：状态机表驱动（非法流转 409）；执行中→飞机 flying+任务文本=工单标题；结案→飞机释放回待命、任务目标清除、被占用航线回 planned 并落盘。工单不是纸面数据，是状态中枢。

**Q10：评分权重为什么这样设？**
A：距离 40% + 电量 30% + 空闲度 20% + 机型能力 10%：先保证"能到场"（距离+电量 70%），再看"谁更闲"（空闲），最后"机型是否适配"（能力）。应急任务把距离提到 60%——应急优先到场速度。权重可配置，是规则不是黑盒。

**Q11：到达目标后飞机会怎样？**
A：悬停（目标保留）。这对应"到场执行任务"的语义；工单结案后释放回待命。沿航线执行时到达当前航点自动切换下一航点。

### 安全合规

**Q12：登录安全做了哪些？**
A：① 验证码一次性（内存 Map，5 分钟过期，登录即销毁）；② JWT 2h 短时、issuer/audience 双校验；③ 生产强制改默认密码（config 校验）；④ 写接口（派发/工单流转/下线/建航线）requireRole('operator','admin')；⑤ helmet 安全头 + 严格 CORS；⑥ 容器 read_only + cap_drop ALL + 非 root。

**Q13：token 为什么存 sessionStorage 而不是 localStorage？**
A：sessionStorage 关标签即失效，降低 XSS 窃取后的暴露窗口（演示口径；生产应 HttpOnly Cookie + CSRF 防护，这是已知改进项）。

**Q14：前端伪造角色怎么办？**
A：角色校验在**后端**（requireRole 中间件），前端角色只用于 UI 显隐（隐藏入口）；伪造 sessionStorage 只能骗自己，调用写接口会被 403。

**Q15：敏感数据（空域/警务）怎么处理？**
A：只展示聚合口径（方舱数、架次、组织排行），不展示个人级明细；材料里"空域/警务敏感数据不展示个人级明细"原则已写入 CLAUDE.md 并遵守。

### 算法细节

**Q16：冲突检测为什么用 Haversine？**
A：球面两点距离要考虑地球曲率；在 900m 量级平面近似误差可忽略，但 Haversine 是标准做法、实现干净（经纬度→弧度→大圆距离），且与航线里程计算复用同一函数。

**Q17：禁飞区判定算法？**
A：射线法（Ray Casting）：从点向任意方向引射线，与多边形边相交次数为奇数则在内部。复杂度 O(n)（n=边数），演示 3 个多边形足够；点-to-线段距离用于"临近预警"扩展。

**Q18：续航预测公式？**
A：剩余分钟 = 电量% × 额定续航（M350 55min / M30T 41min / M3E 45min）；返航阈值 = （去程距离/巡航速度）/额定续航 × 100% × 1.25 安全系数；电量 ≤ 40% 触发 low-battery 告警（每机只报一次）。

**Q19：告警怎么去重？**
A：每连接维护状态 Map：禁飞区按"机:区"去重（离开后复位）、冲突按"机对"去重（解除后复位）、低电量按机去重（持续低电不轰炸）——同一事件只在状态变化时推送一次。

**Q20：SSE 断线重连会丢数据吗？**
A：前端指数退避（1s→2s→…→30s 封顶 + 抖动）自动重连；飞机位置是"当前状态"而非事件流，重连后收到最新快照即恢复；位置写回保证不跳变。

### 前端与体验

**Q21：多分辨率怎么适配？**
A：大屏 grid 三栏 + `clamp()` 弹性列宽 + 断点（≤1250px 两栏、≤820px 单列）；E2E 在 9 种分辨率（含 7680×1440 和 390×844）断言无横向溢出。工作台左右分栏在 ≤1180px 堆叠。

**Q22：实时更新为什么页面不卡？**
A：① 时钟独立组件每秒重渲染隔离；② SSE 2s 一帧只更新 ref 数据，Vue 细粒度响应；③ ECharts 按需引入（tree-shaking）；④ 列表滚动容器隔离（overscroll-behavior + scrollbar-gutter）；⑤ 30s 轮询静默刷新不打断交互。

**Q23：无障碍做了什么？**
A：axe serious/critical = 0；状态多通道（颜色+图标+文字）；按钮 title/aria-label 全覆盖；焦点环可见；触控 ≥40px（移动 44px）；prefers-reduced-motion 全局降级；高德 iframe title/logo alt 补丁 + 重试。

**Q24：为什么工作台地图在左、面板在右？**
A：GCS（地面站）惯例——态势地图是背景，操作面板是主体；列表获得全高，调度候选/工单展示量翻倍；地图可 52% 宽、左导航可折叠成图标条，面板空间最大化。

**Q25：白屏事故是怎么回事？怎么发现的？**
A：HTTP 资源全 200 但浏览器白屏——用无头浏览器真实渲染抓请求，发现 CSP `upgrade-insecure-requests` 把资源强制升级 HTTPS 而服务器无 SSL，全部 ERR_SSL。修复：移除该头 + 新增 HTTPS 入口。**教训：状态码 200 不等于页面可用，要用真实浏览器验证。**

### 扩展与边界

**Q26：怎么接真实无人机？**
A：扩展点已预留：① SSE 数据源替换（data.nextAircraftSnapshot → IoT/MQTT 网关）；② 调度引擎规则可配置；③ 接口契约不变。真实接入需要：MQTT 遥测、RTK 定位、飞控指令下行（超 BFF 范围，设计方案文档已注明）。

**Q27：为什么 S6 图像识别、S9 问答不做？**
A：材料（ECHO-04）自己列了风险：S6 无历史样本/无标注/95% 无基线；S9 无指标字典/跨部门越权/SQL 沙箱/幻觉兜底。**没有数据却承诺 AI 效果**正是 Echo 材料被批评的两点。本期只做规则可解释的智能，S6 保留演示事件流、S9 入口置灰，数据条件成熟后单独立项。

**Q28：多委办局数据隔离怎么做？**
A：当前单用户演示（admin 持全角色）。隔离需要组织树 + 数据域权限（设计方案 G-06），依赖业务方提供组织数据——已列为下一轮；后端 RBAC 骨架（viewer/operator/admin）已就绪。

**Q29：演示数据可信吗？会穿帮吗？**
A：演示数据全部本地确定性生成、无外部依赖；凡是"演示口径"都在 UI 标注（"演示底图 · 待配置高德 Key""演示数据 · 待接入识别模型"）；业务逻辑（调度/冲突/工单/持久化）是真实实现的规则，不是写死的假数据——比如派发的飞机真的飞、工单真的流转、航线真的落盘。

**Q30：后续规划？**
A：① 多账号登录（viewer/operator）；② 告警转单状态后端化（多终端同步）；③ 作业台点选"清除目标点"+调度审计；④ S9 立项先做指标字典与查询白名单；⑤ 真实设备接入（MQTT/RTK）；⑥ 组织数据域隔离。
