> 版本：v1.3  
> 日期：2026-08-14  
> 依据：`FDE实操需求文档-无人机低空智慧调度平台.md`、`files/学员材料-Echo阶段输出材料包/`（ECHO-01~05）、`docs/场景模块补全实施计划.md`、`docs/场景对照与大屏作业台分离规划.md`、当前代码

## 一、做了什么

面向市级指挥中心的暗色驾驶舱：登录后进入态势大屏，调度员进入作业工作台。栈为 Vue 3.5 + TypeScript + Vite + Pinia + ECharts + 高德 JS API 2.0，后端是 Node.js BFF，Docker Compose 部署。

| 路由 | 角色 | 形态 | 职责 |
|---|---|---|---|
| `/login` | 未登录 | 左右分栏登录 | 用户名 / 密码 / 4 位验证码 |
| `/` | `dashboard.viewer` | 68px 顶栏 + 三栏 + 28px 页脚 | 只读态势：总览、案例、地图、排行、分析、告警 |
| `/workspace` | `operator` / `admin` | 64px 顶栏 + 264px 导航 + 地图 + 作业面板 | 调度、工单、健康、AI 事件处置 |

材料来源：Echo 阶段 10 场景清单 + FDE 实操需求 + 大屏接口 mock。原则是**规则可解释、不承诺没有数据的 AI**。

| 场景 | 材料需求 | 当前实现 | 怎么做的 | 状态 |
|---|---|---|---|---|
| **S1 态势总览大屏** | 资源概况、飞行案例 TOP10、任务排行、统计分析、三底图一张图 | `DashboardView`：三栏 + 高德/演示底图 + SSE 遥测 + 告警抽屉 + 回放小窗 | 左列总览/案例，中列地图+KPI，右列仅排行/分析；多分辨率 E2E | ✅ 生产级 |
| **S2 智能调度推荐** | 自动推荐派哪架机 | `DispatchPanel`：候选过滤 + 加权评分 + 可解释理由 | 距离 40% / 电量 30% / 空闲 20% / 机型 10%；应急权重上调；二次确认后落库工单 | ✅ |
| **S3 空域冲突预警** | 多机自动预警 | 后端 Haversine 双阈值（注意 900m / 严重 450m）+ 高度差 80m | SSE `conflict` 事件 → 大屏 toast + 告警抽屉可定位 / 转工单 | ✅ |
| **S4 续航预测与返航** | 预判剩余电量、提醒返航 | 机型额定续航（M350 55 / M30T 41 / M3E 45）× 电量 + 安全系数 1.25 | 飞机弹窗显示剩余分钟；≤40% 推 `low-battery` | ✅ 规则版 |
| **S5 禁飞区合规** | 近禁飞区预警 / 强制返航展示 | 3 个多边形（虹桥净空、龙华周边、临时活动区）+ 射线法点-in-多边形 | 地图 Polygon + 违规红色脉冲 + SSE `nofly` | ✅ |
| **S6 图像识别异常** | 95% 准确率识别事故/火情/聚集 | 演示事件流（置信度 0.72–0.96），标注「演示数据 · 待接入识别模型」 | 确认 / 转派 / 归档走后端状态机；转派带坐标进调度 | ⚠️ 演示 |
| **S7 巡检工单闭环** | 自动生成计划 + 工单流转 | 状态机：待接收 → 已接收 → 执行中 → 已完结 | 日/周计划生成、告警/派发/保养均可建单、展开可预览航线 | ✅ |
| **S8 应急智能派单** | 事件联动最近机 | 并入 S2：应急类型 + 最近机权重上调 | AI 转派 / 告警转单预填应急坐标后重算推荐 | ✅ |
| **S9 数据智能问答** | 聊天查数据出图表 | 工作台入口禁用 | 材料列了 4 项风险：无指标字典、跨部门越权、SQL 沙箱、幻觉兜底 | ⏸️ 暂缓 |
| **S10 设备健康预测** | 预测保养 / 故障 | 健康分 + 电池/电机/桨叶寿命阈值 | 低分或部件剩余 <15% 可一键生成保养工单 | ✅ |

**取舍说明：** S6 不做真模型、S9 不做自然语言 SQL，正是 Echo 材料被批评的两点——「没有数据却承诺 AI」「能力假设过于乐观」。本期只做能讲清楚规则的智能。

## 四、怎么设计、怎么实现

### 4.1 总体架构

```
浏览器
  Vue 3 + Pinia + Vue Router
    /login          LoginView
    /               DashboardView（只读态势）
    /workspace      OpsWorkbench（可写作业）
        ↓  Bearer JWT
Node BFF  apps/api
    /api/v1/auth/*
    /api/v1/dashboard/*  /flight-records  /flight-routes  /metrics
    /api/v1/geo/*        禁飞区、冲突
    /api/v1/dispatch/*   推荐、派发
    /api/v1/work-orders  列表、流转、生成、从告警/保养创建
    /api/v1/aircraft/health
    /api/v1/events/ai-recognition  列表 + 状态流转
    SSE /api/v1/realtime/aircraft  飞机快照 + nofly/conflict/low-battery
        ↓
内存确定性数据（data.ts + scenarios.ts + geo.ts）
```

前端不直连业务库。实时位置走 SSE，统计走 30s 静默轮询，失败保留 last-good。

### 4.2 前端分层

| 层 | 位置 | 职责 |
|---|---|---|
| 视图 | `apps/web/src/views/` | 大屏总线、作业台骨架、登录 |
| 面板 | `components/DispatchPanel` 等 | 调度 / 工单 / 健康 / AI 事件 |
| 地图与回放 | `OperationsMap`、`ReplayDialog` | 高德三底图 + 无 Key 演示底图；独立回放窗 |
| 组合逻辑 | `composables/useAircraftStream`、`usePolledResource`、`useRealtimeAlerts` | SSE 退避重连、轮询、告警/toast |
| 契约 | `types.ts` + `services/api.ts` | 禁止 any；401 清会话回登录 |
| 样式 | `styles/tokens/` + `main.scss` | 只准用 CSS 变量；`--accent` / `--warning` / `--alert` |

### 4.3 后端关键规则

- **调度评分**：待命优先，告警且电量过低剔除；应急提高距离权重。
- **工单来源**：`plan` / `alert` / `dispatch` / `maintenance`，派发成功会真正写入工单列表（不再只返回假 taskId）。
- **AI 事件**：`reviewing → confirmed → archived`，非法流转 409。
- **鉴权**：登录发 JWT（默认 admin 持 viewer+operator+admin）；写接口 `requireRole('operator','admin')`。

### 4.4 交互与体验上补过的点

- 大屏与作业台分离后，viewer 看不到作业台入口；越权进 `/workspace` 打回大屏并 toast。
- 告警抽屉可「转工单」，跳转工作台并高亮新单。
- 作业台嵌入可折叠小地图；点飞机或吃 URL 参数重算推荐。
- AI「转派」带经纬度进调度，不再只切页签。
- 健康低分可生成保养单。
- 按钮热区 ≥40px，`:active` 缩放，补 `title` / `aria-label`。
- 通知：从右上角改为**底部居中**，避免挡住刷新 / 全屏 / 作业台 / 地图工具。作业台**不再弹实时告警**，只显示派发、转单、预览失败等操作反馈，且每条有关闭按钮。

## 六、v1.2 逻辑闭环强化与工作台布局（第三轮）

> 动因：用户验收时发现「派发是纸面操作」——派发/工单流转只写数据，飞机状态与地图位置完全不动，链路断在中间。本轮审计全部状态流转后补齐闭环。

### 6.1 断环审计结论（修复前）

| 环节 | 修复前 | 修复后 |
|---|---|---|
| 派发 → 飞机状态 | ❌ 飞机仍是 standby，地图不动 | ✅ `applyDispatch`：standby/warning → flying，任务文本更新 |
| 派发 → 飞行轨迹 | ❌ 无目标概念 | ✅ `dispatchTargets`：SSE 快照驱动飞机直线飞向任务点（航向跟随、到达悬停、位置写回累计） |
| 派发 → 防重复 | ❌ 同一架飞机可反复被派 | ✅ 候选排除「已有未完结工单」的飞机 + 电量 <25% 剔除 |
| 工单 received→executing | ❌ 纸面流转 | ✅ 联动飞机起飞（flying + 任务文本 = 工单标题） |
| 工单 executing→completed | ❌ 完成不释放 | ✅ 联动飞机释放（standby + 「待命」 + 清除任务目标） |
| 低电量/禁飞区转工单 → 处置完成 | 部分断 | ✅ 工单结案同时复位飞机，告警处置闭环 |
| AI 事件转派 → 飞机到场 | ❌ 派发后飞机不飞向事件坐标 | ✅ 转派坐标成为任务目标，飞机实际飞抵 |

### 6.2 实现

- `data.ts`：新增 `dispatchTargets`（飞机→目标坐标）+ `nextAircraftSnapshot` 目标飞行分支（写回位置保证 SSE 重连后连续）
- `scenarios.ts`：新增 `applyDispatch`；`recommendDispatch` 防重复过滤；`transitionWorkOrder` 联动飞机起飞/释放
- `app.ts`：派发接口接入 `applyDispatch`，返回文案改为「飞机已出动」
- 新增 2 条 API 闭环测试（派发联动+防重复 / 工单流转联动），API 测试 17 → 19 条

### 6.3 工作台布局优化

- **问题**：作业台右侧为「地图在上（280px）→ 面板在下」，列表可用高度不足，调度候选/工单列表展示受限
- **方案**：改为 **GCS 式左右分栏** —— 地图在左（min 360px / 44%）、操作面板在右（全高 56%），列表展示量翻倍
- 折叠地图后收成 44px 窄条，面板独占全宽（折叠按钮带方向图标 ChevronRight/Down）
- 断点：≤1180px 恢复上下堆叠（地图 300px 高）；≤820px 移动端保持纵向 + 44px 触控
- 地图工具条/图例/弹窗在窄列下回归验证无重叠

### 6.4 验证

- typecheck / test（API 19 + Web 24 = 43 条）/ build 全绿
- e2e 19 条全绿（工作台布局改动未破坏面板切换与角色守卫用例）
- 手动链路验证：派发 UAV-07 → `/api/v1/aircraft` 状态变 flying、任务变「巡检任务」；SSE 逐帧向目标点移动（lat 31.207→31.211→31.214→…，航向 356°）

## 七、v1.3 方舱下钻 / 航线规划 / 设备下线（第四轮）

> 动因：用户验收提出三点——「点击方舱能看到里面有哪些无人机并直接调度」「支持航线规划」「设备应能下线」。评估后全部落地（演示版），并同步补上航线搜索与「规划航线同步进首页目录」。

### 7.1 方舱下钻（S1 扩展）

- 后端新增方舱表：6 个启用（带位置/备注，与飞行记录 deviceName 1~6 号方舱一致）+ 5 个规划中（只计数）；飞机挂 `shelterId`
- `GET /v1/shelters` 返回方舱及驻泊无人机聚合
- 地图（双底图）显示方舱标记（Warehouse 图标 + 序号标签），点击弹窗：方舱名/备注/驻泊列表（名称、机型、状态、电量）
- 每架无人机「去调度」：大屏（operator/admin）跳转 `/workspace?module=dispatch&aircraftId=xx` 预选该机；作业台内直接切调度面板预选；**已下线飞机置灰禁点**；候选不存在时提示原因（下线/任务中/电量不足）

### 7.2 航线规划与沿航线执行（S2 扩展）

- 作业台地图头部「规划航线」模式：连续点击地图加点（高德/演示双模式），实时显示折线与航点，命名保存（2~20 点）
- `POST /v1/flight-routes`：距离/时长按 Haversine + 巡航 12m/s 推算，**保存即进入首页「飞行航线目录」**（大屏 30s 轮询同步），预览使用真实航点
- 派发面板新增「执行航线（可选）」：可搜索（名称/单位过滤），选中后派发带 `routeId` → 飞机**沿航点序列依次飞行**（到达切下一航点），航线置 `active` 并绑定飞机；**工单结案自动释放**回 `planned`
- 首页航线目录抽屉新增搜索框（名称/单位关键词）

### 7.3 无人机下线/恢复（S10 扩展）

- 设备健康面板每行新增「下线/恢复」按钮：下线 = 停用（候选剔除、遥测悬停、不参与冲突/告警检测、地图置灰、任务置「已下线」），恢复 = 回待命
- 后端 `POST /v1/aircraft/:id/offline`（operator/admin），健康接口同步返回 `offline` 字段

### 7.4 工作台布局微调

- 地图列 44% → **52%**（地图加宽、右侧面板收窄）；左侧功能导航支持折叠成 64px 图标条（`PanelLeft` 开关，面板独占全宽）

### 7.5 验证

- typecheck / test（API 23 + Web 24 = 47 条，新增 5 条：航线创建搜索、方舱下钻、下线过滤、沿航线派发与释放、闭环回归）/ build 全绿
- e2e 19 条全绿（新增功能不影响既有矩阵）

## 九、代码架构上做了哪些处理

1. **读写分离**：大屏只读，作业写入独立路由和角色。
2. **实时与统计分离**：SSE 推飞机与合规事件；排行/工单/健康走 REST + 轮询。
3. **规则可解释**：调度理由、续航公式、冲突阈值、健康分都能在 UI 上读到，不装黑盒模型。
4. **演示可降级**：无高德 Key 用本地网格底图；地图 CDN 失败可重试；E2E 覆盖回退。
5. **组合函数抽离**：`useAircraftStream` / `usePolledResource` / `useRealtimeAlerts` 给两页复用，避免再把 SSE 抄两遍。
6. **设计约束落地**：token 三主色、等宽数字、PanelShell 三态、reduced-motion、触控尺寸。
7. **安全底线**：验证码一次性、JWT 短时、写接口角色校验、前端不信任客户端伪造部门。
